# FI1 — FT-009 Sign-in page + flow

## What shipped

- `projects/domain/src/lib/sign-in-page/sign-in-page.component.{ts,html,scss}` — `pu-sign-in-page`. Reactive form with email + password (`Validators.required`, `Validators.email`). Wires `@Inject(AUTH_SERVICE) auth: IAuthService` and calls `auth.signIn(...)`. On 200 the AuthService stores both access + refresh tokens, then the page routes to `/home`. On 401 surfaces "Invalid email or password." On 429 surfaces "Too many attempts. Please wait a moment and try again." Otherwise generic. Composes `BrandLogoComponent` and renders `routerLink="/password-reset"` + `routerLink="/sign-up"` link affordances.
- `projects/pull-up/src/app/app.routes.ts` — added `/sign-in` route (lazy-loaded standalone component).
- `projects/domain/src/public-api.ts` — exports `SignInPageComponent`.

## Acceptance test (ATDD — Playwright POM)

- `frontend/e2e/pages/sign-in-page.ts` — `SignInPagePom` with `email`/`password`/`submit`/`serverError`/`forgotLink` locators (via `data-testid`).
- `frontend/e2e/sign-in-flow.spec.ts` — 2 scenarios × 2 projects (desktop + mobile) = 4 tests:
  1. **Happy path** — mocked `/api/auth/sign-in` 200 with both tokens; mocked `/api/users/me` returns the profile; the page navigates to `/home`; `localStorage` contains `pullup.access-token` + `pullup.refresh-token`.
  2. **Invalid credentials** — mocked `/api/auth/sign-in` 401; the page stays on `/sign-in` with the generic "Invalid email or password." server error.
