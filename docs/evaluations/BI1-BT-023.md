## Behavior

The hosted service ticks every minute via `PeriodicTimer`. Each tick creates a scope, resolves `ISender`, and sends `DispatchEventRemindersCommand`. The handler joins `Rsvps` to `Events`, filters by status (`Going`/`Maybe`), event status (`Scheduled`), reminder-not-yet-sent, then narrows client-side to events starting in `[now+23h, now+25h]` (same client-side date filter pattern as `ListMyEvents` for SQL Server / SQLite parity). For each candidate it marks the row `ReminderSentAt = now` and saves; **after** the save, it fans out `DispatchInvitationNotificationCommand(EventReminder)` per recipient — the existing dispatcher gates on the recipient's `NotificationPreference.EventReminders`. Marking first, dispatching second, means a sender outage cannot replay reminders on the next tick.
