# FI1 — FT-018 Event cancel action

## What shipped

- `EventDetailPageComponent` extended:
  - `ConfirmCancelDialogComponent` defined inline (same `.ts` file): Material dialog with a confirmation message; "Confirm" button closes with `true`, "Dismiss" closes with `false`.
  - `MatDialog` injected into `EventDetailPageComponent`.
  - `cancelSubmitting` signal tracks in-flight cancel request.
  - `onCancelEvent()` method: opens `ConfirmCancelDialogComponent`; on `true` calls `EVENTS_SERVICE.cancel(id)`, then re-fetches the event so the cancelled-status banner renders.
  - "Cancel event" `mat-stroked-button color="warn"` added to `detail-host-actions` section (host-only, hidden for already-cancelled events).
  - `data-testid="detail-cancel-button"` on the button.
- `EventDetailPagePom` updated: added `cancelButton` locator.
- **Backend GuestSummary bug fixed** (discovered during this task):
  - `GuestSummary.cs` record: added `Guid InvitationId` parameter.
  - `GetEventQueryHandler.cs`: passes `i.Id` when constructing each `GuestSummary`.
  - `frontend/projects/api/src/lib/events/guest-summary.ts`: added `invitationId: string`.

## Acceptance test (Playwright POM)

- `e2e/event-cancel-flow.spec.ts` — 2 scenarios × 2 projects = **4 tests**, all passing.

The tests verify:
1. **Host cancels:** opens detail → clicks Cancel → confirms dialog → mocked `POST /api/events/:id/cancel` returns 204 → page re-renders with cancelled banner.
2. **Non-host:** event detail loads as non-host → cancel button is not present.
