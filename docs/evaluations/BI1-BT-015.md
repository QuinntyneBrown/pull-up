## Behavior

Handler re-verifies the password via `IPasswordHasher.Verify` (failure → `InvalidCredentialsException` → 401), then in one transaction:

1. **Cancels future hosted events** by reusing `CancelEventCommand` per event id. That handler already audits + fans out `EventCancelled` notifications, so we get the full cascade for free.
2. **Removes the user from active invitations on future events** (sets `Invitation.RemovedAt`).
3. **Revokes all active refresh tokens** for the user (each `RefreshToken.Revoke(now)`).
4. **Tombstones the User row** itself.

Identity filtering happens in SQL; date narrowing happens client-side (`StartsAtUtc > now`) to stay portable across SQL Server and SQLite — same pattern established in `ListMyEvents` and `DispatchEventReminders`.
