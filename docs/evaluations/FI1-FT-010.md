# FI1 — FT-010 Password-reset flow

## What shipped

### Request page (`/password-reset`)

- `projects/domain/src/lib/request-password-reset-page/request-password-reset-page.component.{ts,html,scss}` — reactive form with email (`required` + `email`). Calls `auth.requestPasswordReset({ email })`. **Both success and error responses transition to the same "If an account exists, we sent a reset link…" panel** — no enumeration leak. Renders a "Back to sign in" link.

### Confirm page (`/password-reset/confirm`)

- `projects/domain/src/lib/complete-password-reset-page/complete-password-reset-page.component.{ts,html,scss}` — reads `?token=` from the URL via `ActivatedRoute.snapshot.queryParamMap`. If absent, renders a "Reset link missing" surface (no form). Otherwise renders a reactive form with `newPassword` (`required`, `minLength(8)`). On 204 navigates to `/sign-in` with a `MatSnackBar` "Password updated. Sign in with your new password." On 400 surfaces "This reset link is invalid or has expired. Request a new one." inline. Other errors → generic retry message.

### Routes + exports

- `app.routes.ts` — added `/password-reset` and `/password-reset/confirm` lazy routes.
- `domain/src/public-api.ts` — exports both components.
