# FI1 — FT-001 AuthService completion + AuthStorage refactor

## What shipped

- `AuthStorage` (`projects/api/src/lib/auth/auth-storage.ts`) — single-responsibility wrapper around `localStorage` with `get/set` for access token, refresh token, and serialized current user, plus `clear()`.
- `AuthService` (`projects/api/src/lib/auth/auth.service.ts`) — added `signIn`, `requestPasswordReset`, `completePasswordReset`, `refresh`, `signOut` (Observable<void>, server-aware), `snapshotRefreshToken`. Token persistence now goes through `AuthStorage`.
- `IAuthService` contract updated; `signOut()` signature changed to `Observable<void>`.
- DTOs added: `SignInRequest`, `SignInResponse`, `RequestPasswordResetRequest`, `CompletePasswordResetRequest`, `RefreshAccessTokenRequest`, `RefreshAccessTokenResponse`, `SignOutRequest`.
- `public-api.ts` re-exports the new types and `AuthStorage`.
- `home-page.component.ts` adapted to subscribe to the new `signOut()` Observable.

## Acceptance test

`projects/api/src/lib/auth/auth.service.spec.ts` — 6 tests, all passing:

```
Test Files  1 passed (1)
     Tests  6 passed (6)
```

Asserts each method posts to the expected URL with the expected body and parses the response shape:

- signIn → POST `/api/auth/sign-in`, stores access + refresh
- requestPasswordReset → POST `/api/auth/password-reset` (202)
- completePasswordReset → POST `/api/auth/password-reset/confirm` (204)
- refresh → POST `/api/auth/refresh`, rotates both tokens
- signOut with stored refresh token → POST `/api/auth/sign-out`, then clears local
- signOut without stored refresh token → clears local, makes no HTTP call
