# FI1 — FT-013 Email change request + confirm

## What shipped

- `ProfilePageComponent` extension:
  - Added "Change email" button in the actions section.
  - Implemented `openChangeEmail()` which opens `ChangeEmailDialogComponent` via `MatDialog`.
  - On dialog close (with result), calls `profile.requestEmailChange(result)` and shows a success snackbar with instructions to check the new email.
- `ChangeEmailDialogComponent` (new):
  - Reactive form with `newEmail` (email validator) and `currentPassword` (required).
  - Material 3 dialog styling.
- `ConfirmEmailChangePageComponent` (new):
  - Route `/email-change/confirm`.
  - Reads `token` from query parameters.
  - On mount, calls `profile.confirmEmailChange(token)`.
  - Shows success message and "Back to Profile" button on success; shows `ErrorStateComponent` on failure.
- `public-api.ts` updated to export `ConfirmEmailChangePageComponent`.

## Acceptance test (Playwright POM)

- `e2e/email-change-flow.spec.ts` — 2 scenarios × 2 projects = **4 tests**, all passing.

The tests verify:
1. **Request Flow:** Loading profile, opening dialog, submitting valid change request, and asserting the success snackbar.
2. **Confirmation Flow:** Navigating to `/email-change/confirm?token=xyz`, asserting successful confirmation, and verifying the profile shows the updated email.
