# FI1 — FT-019 Event edit + invitee management

## What shipped

- `EventEditPageComponent` (new, `domain` library):
  - Route `/events/:id/edit` (registered before `/events/:id` to prevent shadowing).
  - Fetches `EVENTS_SERVICE.get(id)` on mount; pre-fills all form fields including UTC→local time conversion.
  - Reactive form: title (required, ≤200), date (mat-datepicker, min = today), time, location (required), description, `allowPlusOne` toggle, `showGuestList` toggle.
  - **Existing guests section** (`edit-existing-chips`): chip per `GuestSummary`; remove-button calls `EVENTS_SERVICE.removeInvitee(eventId, invitationId)` immediately (no deferred submit).
  - **Pending invitees section** (`edit-pending-chips`): chip-input adds email to local `pendingInvitees` signal; ×-chip removes from pending list.
  - On submit: calls `EVENTS_SERVICE.update(...)` → then `addInvitee` for each pending invitee → navigates to `/events/:id`.
  - Discard button navigates back to `/events/:id` without saving.
- `public-api.ts` updated to export `EventEditPageComponent`.

## Acceptance test (Playwright POM)

- `e2e/event-edit-flow.spec.ts` + `e2e/pages/event-edit-page.ts` — 3 scenarios × 2 projects = **6 tests**, all passing.

The tests verify:
1. **Edit title, save:** form pre-filled with existing event data; change title; submit → navigates to detail.
2. **Add pending invitee:** type email → Add → chip appears in pending section; remove chip → pending section hidden.
3. **Remove existing guest chip:** existing invitee chip visible; click × → `DELETE /api/events/:id/invitees/:invId` called; chip disappears.
