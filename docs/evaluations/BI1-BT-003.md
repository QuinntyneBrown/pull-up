## Behavior in plain English

When the API receives any JSON-bodied write request, it logs one Information entry containing the method, path, and body — but the body is run through `JsonBodyRedactor` first. Sensitive property values are replaced with the literal string `***REDACTED***`. The redactor is a pure function so it can be unit-tested in isolation or applied anywhere else in the codebase (e.g., to outgoing webhooks later).

Non-JSON bodies pass through unredacted (form posts, multipart uploads, etc.). Malformed JSON returns the original string — the middleware never throws because of bad input. The middleware always rewinds `Request.Body` so downstream binders see the same bytes the client sent.

### Two corrections during implementation

1. `TestWebApplicationFactory` was `sealed`, blocking the subclass needed for log capture. Unsealed it (and added `base.ConfigureWebHost(builder)` so subclasses compose with the base wiring rather than replace it).
2. The test factory's appsettings filtered out Information logs, so the captured entries collection was effectively empty. Raised the default log level for the Testing environment to Information, kept ASP.NET Core and EF at Warning to avoid framework noise.
