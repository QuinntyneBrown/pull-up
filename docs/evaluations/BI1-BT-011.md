## Behavior

Handler hashes the supplied raw token, finds the row, rejects with `InvalidPasswordResetTokenException` if missing / used / expired. The same exception is thrown for any non-existing user (defensive). On success: hashes the new password via the BT-001 MVP `IPasswordHasher` (PBKDF2 600k iterations), invokes `User.ChangePassword(newHash, now)`, marks the reset row used, **revokes every active refresh token for the user** (L2-009 requirement: completing a reset forces all existing sessions to re-authenticate), and saves once. The command is `[AuditedAction("PASSWORD_RESET_COMPLETED")]`.

The validator enforces L2-003 complexity: ≥8 chars, ≥1 digit, ≥1 non-alphanumeric symbol — identical to the registration validator so policy stays consistent.
