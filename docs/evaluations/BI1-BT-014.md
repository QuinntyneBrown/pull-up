## Behavior

The new entity stores one row per user keyed by `UserId` with three booleans. `Register` extends the existing handler to persist a default-on row alongside the new `User`. The `GetNotificationPreferences` query falls back to `DefaultFor(userId)` if no row exists (defensive — covers users who pre-date this slice). `UpdateNotificationPreferences` upserts via `Update(...)` (creates the row if absent). `[AuditedAction("USER_NOTIFICATION_PREFS_UPDATED")]`.
