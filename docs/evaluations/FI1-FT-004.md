# FI1 — FT-004 Interceptor 401-refresh + error interceptor + app providers

## What shipped

### Auth interceptor (`projects/pull-up/src/app/auth-jwt.interceptor.ts`)

- Attaches `Authorization: Bearer <token>` when `auth.snapshotAccessToken()` is non-null.
- On `HttpErrorResponse` status 401:
  - Returns the error untouched if the request is to `/api/auth/refresh` or `/api/auth/sign-in` (avoid loops).
  - Returns the error untouched if the request has already been retried (`HttpContextToken<boolean> RETRIED`).
  - Returns the error untouched if no refresh token is stored.
  - Otherwise calls `auth.refresh(refreshToken)`; on success retries the original request with the new bearer; on refresh failure calls `auth.clearSession()` (sync, no server call) and navigates to `/sign-in`.

### Error interceptor (`projects/pull-up/src/app/error.interceptor.ts`)

- Surfaces non-form / non-auth errors via `MatSnackBar`:
  - status 0 → "Network error. Check your connection and try again."
  - 5xx → "Something went wrong on our end. Please try again."
  - 403 → "You don't have permission to do that."
  - 404 → "Not found."
  - 429 → "Too many attempts. Try again in a moment."
  - 400 (validation), 401 (handled upstream), 409 (handler-specific) → silent; surfaced inline by callers.

### `IAuthService` / `AuthService`

- Added `clearSession(): void` — clears local tokens + user + emits null to subjects without an HTTP call.
- `signOut()` refactored to delegate to `clearSession()`.

### `app.config.ts`

- Registers `PROFILE_SERVICE` (`useExisting: ProfileService`) and `EVENTS_SERVICE` (`useExisting: EventsService`) alongside `AUTH_SERVICE`.
- `withInterceptors([errorInterceptor, authJwtInterceptor])` — error wraps auth so it only catches what auth's refresh-retry didn't handle.

### `app.spec.ts`

- Replaced the stale scaffold "should render title" assertion (the MF1 app shell is just `<router-outlet />`); kept a `should create the app` smoke that wires `provideRouter([])`.
