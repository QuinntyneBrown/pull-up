## Notes for downstream

- **Refresh-token rotation (BT-008)**: the response now ships a raw refresh token + its expiry; BT-008 (`POST /api/auth/refresh`) will accept that raw value, look it up by hash, rotate, and return a new pair.
- **Rate limiter (BT-007)**: this slice intentionally does **not** include rate limiting; BT-007 wraps `SignInUserCommandHandler` with `ISignInRateLimiter`. Keeping the slices separate per BT1's sizing rule.
- **Sign-out (BT-009)**: the persisted `RefreshToken` row is the surface BT-009 will revoke.

## Done

BT-006 is complete. Pull Up users can sign in with email + password, receive a JWT access token and an HMAC-hashed refresh token, and all success / failure events land in the audit log.
