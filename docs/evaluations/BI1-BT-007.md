## Design notes

- **State scope**: per-process (`IMemoryCache`). For a multi-instance App Service this would back to Redis; that swap is one provider change behind the same `ISignInRateLimiter` interface — no caller changes needed.
- **Key normalization**: emails are trimmed + lowercased before keying so `Rosa@Example.com` and `rosa@example.com` share a counter, matching L2-001/L2-002's email-uniqueness rule.
- **Window expiry**: `IMemoryCache.Set(key, value, Window)` uses an absolute expiry from the most recent failed-attempt write. The counter survives across attempts within the window and self-destructs 60 s after the last failure — sliding from the last failure, not the first.
- **Successful sign-in clears the counter** — a user who eventually gets their password right is not locked out by their earlier typos.
