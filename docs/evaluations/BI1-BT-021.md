## Behavior

`AddInvitee`: host-only via `IAuthorizationRequirement`. Handler normalizes the email, returns success without writing if an active invitation already exists for that email + event (idempotent), looks up the user by email (nullable), creates the `Invitation` row, saves, then dispatches `EventInvited` to the matched user (skips dispatch for email-only invites — no user id yet). `[AuditedAction("EVENT_INVITEE_ADDED")]`.

`RemoveInvitee`: host-only. Loads the invitation scoped to the event id (404 if absent or wrong event). Calls `invitation.Remove(now)` and **deletes the corresponding `Rsvp` row** if the invitee had one. `[AuditedAction("EVENT_INVITEE_REMOVED")]`.
