# FI1 — FT-014 Delete account page

## What shipped

- `DeleteAccountPageComponent` (new, `domain` library):
  - Route `/profile/delete`.
  - Reactive form with `currentPassword` (required) + an `iUnderstand` checkbox (required).
  - On submit, calls `PROFILE_SERVICE.deleteAccount({ currentPassword })`.
  - On 204: clears tokens via `AUTH_SERVICE.signOut()` and navigates to `/sign-up` with a "Account deleted" snackbar.
  - On 400/401: surfaces the server error message inline on the password field.
- `ProfilePageComponent` updated: added a "Delete account" destructive link that navigates to `/profile/delete`.
- `app.routes.ts` updated: added `/profile/delete` route before `/profile` (guard ordering preserved).
- `public-api.ts` updated to export `DeleteAccountPageComponent`.

## Acceptance test (Playwright POM)

- `e2e/delete-account-flow.spec.ts` + `e2e/pages/delete-account-page.ts` — scenarios × 2 projects = **4 tests**, all passing.

The tests verify:
1. **Wrong password:** submitting incorrect password keeps user on the page and shows error.
2. **Correct password:** submitting correct password navigates to `/sign-up`.
