## Behavior

Handler pulls candidate events with a single SQL query — host or active invitation membership only. Scope filter (`Hosting` / `Invited` / `Past` / default `All`) is applied **client-side** on the materialized list because `DateTimeOffset` comparisons translate inconsistently across SQL Server and SQLite (the test factory hit a 500 on the SQLite path until this was moved client-side). Per-event RSVPs for the current user are fetched in one batch and joined by `EventId`. Results are projected to `EventSummary(Id, Title, StartsAtUtc, Location, Status, IsHost, MyRsvpStatus)` and grouped into four buckets — `ThisWeek` (next 7 days), `LaterThisMonth` (7-day mark → end of current month), `NextMonth` (next month), `Past` (before `now`). Within each bucket events are ordered chronologically (ascending for future buckets, descending for past) via client-side `OrderBy`.

### One correction during impl

First implementation applied the scope filter (including `Where(e => e.StartsAtUtc < now)`) on the SQL side; SQLite returned a 500 on the `Past` test. Moved date filtering client-side after `ToListAsync`. The SQL query still filters by identity (host or invitation membership), which is the high-selectivity predicate; date filtering on the resulting candidate set is cheap. Documented in the handler comment so future contributors don't re-introduce the SQL-side comparison.
